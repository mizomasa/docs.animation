Skills over MCP ― サーバーが「使い方の説明書」まで配る

MCPサーバーはこれまでツールとリソースを配ってきました。Skills over MCP では、そこに「スキルの配布」が加わります。 スキルとはツールの使い方の手順・ベストプラクティス・ワークフローをまとめた指示書で、接続時に発見され、必要になったときだけ本文が読み込まれます。 発見から実行、更新までの流れを7ステップで再生できます。

SUMMARY

概要

Skills over MCP は、MCPサーバーがツールやリソースに加えて「スキル」――ツールの使い方の手順やワークフローをまとめた指示書――まで配布できるようにする拡張です。

スキルは接続したときに名前と短い説明だけが分かり、本文はタスクに必要になった時点で初めて読み込まれるため、コンテキストを圧迫しません。

スキルはサーバーと一緒に更新されるので、開発者はツールと使い方を1回のリリースで配れ、使う側は別途インストールする手間がありません。

BACKGROUND

背景 — 道具は配れたが、「使い方」が付いてこなかった

ツールがあることと、使いこなせることは別だった

MCPによって、サーバーが提供するツールの一覧は接続するだけで手に入るようになりました。名前と説明と入力スキーマがあれば、モデルは「どのツールを、どの引数で呼ぶか」を決められます。けれど実務の作業は、ツールを1回呼べば終わるものばかりではありません。変更前にバックアップを取る、プレビューで確認してから公開する、といった手順の組み立てや、サービスごとの作法やベストプラクティスは、ツールの説明文だけでは伝わりきらない部分でした。

説明文は、ツールの定義に付く短い文章です。そこに作業手順のすべてを詰め込むと、今度は一覧を受け取るだけでコンテキストが膨らんでしまいます。かといって短くすれば、手順の知識はモデルの推測任せになります。「道具の定義」と「作業の進め方」は、本来は別の文書として持つべきものでした。足りなかったのは、その進め方をまとめた文書――スキル――を、誰がどうやって届けるかという仕組みです。

説明書は、作った側がいちばんよく知っている

その「使い方」をまとめたものがスキルです。本文の SKILL.md と補助ファイルからなるディレクトリで、Agent Skills として形式が定められ、2025年12月にはオープン標準になりました。ただ従来は、スキルを使う側が自分で探してインストールするもので、ツールを提供するサーバーとは別々に配られていました。ツールの仕様が変わっても説明書が古いまま、といったズレが起きる構造です。

ないとどうなるか

使い方の伝達手段がなければ、モデルはツールの説明文だけを頼りに手順を毎回その場で組み立てることになり、品質は試行錯誤の出来に左右されます。ベストプラクティスは利用者ごとに個別のプロンプトやメモとして散らばり、サーバーの開発者がせっかく持っているノウハウも届きません。2026年11月24日、MCP公開2周年に合わせて発表された Skills over MCP は、この「説明書の配り方」そのものを規格の側で解決しようとするものです。

        READING
        
仕組みを文章で読む — 発見・選択・読み込み・実行

      

      

        
アニメーションを再生しなくても流れが追えるよう、7ステップの内容を文章でもたどっておきます。

        
発見は接続時、本文は必要になってから — 段階的開示

        
接続すると、サーバーは server/discover で resources の能力と skills 拡張（io.modelcontextprotocol/skills）への対応を宣言します。続く skills/list や skills/get で返ってくるのは、スキルの名前と短い説明といったメタデータだけです。本文はまだ送られてきません。スキルが何十件あっても、接続時に増えるのは目次分だけなので、コンテキストは圧迫されません。この「まず目次だけ、本文は後から」という運び方が段階的開示です。

        
選択はメタデータで、読み込みは resources/read で

        
タスクが来たら、モデルはメタデータの説明と頼み事を照らし合わせ、合うスキルを選びます。選ばれたスキルのファイル実体は、通常のリソースと同じ resources/read で読み込まれます。主文書の SKILL.md に加え、テンプレートなどの補助ファイルも、必要になったものだけが対象です。使うかどうか分からない説明書を全部読み込むことはしません。

        
実行は、スキルの手順に沿ったツール呼び出し

        
読み込まれた SKILL.md には、そのサービスでの作業手順やベストプラクティスが書かれています。モデルはその手順書に沿って、サーバーのツールを順番に組み合わせて実行します。ツール自体は従来どおり tools/call で呼ばれ、結果も同じ形で返ります。変わったのは「どの順番で、何に気をつけて呼ぶか」の知識が、サーバー側から一緒に届くようになった点です。

        
更新はサーバー側で完結する

        
スキルはサーバーの一部として配られるため、開発者がスキルを直せば、次に接続したときには新しい版がそのまま使えます。利用者がスキルだけを別途インストールしたり、更新を追いかけたりする必要はありません。ツールの仕様変更と説明書の改訂を、開発者は1回のリリースにまとめられます。

        
仕様の置き場所 — SEP-2640

        
この仕組みは MCP の拡張仕様として定義されており、仕様提案 SEP-2640 は Final の状態です。一方で、SDKやホスト側の実装は進行中で、使える環境には条件があります。Anthropic の発表では、Claude と Claude Code でパブリックベータとして提供が始まりました。

      


      
      

        NOTES
        
提供状況と広がり

        
2026年11月24日、MCP公開2周年に合わせて Anthropic が発表した内容から、提供条件と周辺の動きをまとめます。

      

      

        

          
利用条件

          
Skills over MCP は Claude と Claude Code でパブリックベータです。Pro / Max / Ultra では既定で有効、Team では管理者が有効化し、Enterprise は近日対応とされています。Claude Code ではバージョン v2.1.331 以降が必要です。

        

        

          
初期パートナー

          
発表時点で名前が挙がった例は、Shopify（ストアのデザインと更新）、HubSpot（オンボーディング手順）、Atlassian（組織情報を踏まえた分析）などで、Carta（株式関連のドラフト）は近日とされています。いずれも「ツールの使い方まで含めて配る」使い方です。

        

        

          
同じ発表の周辺

          
同じタイミングで、長時間タスクを扱う Tasks と、途中で利用者に確認を取る Elicitation が正式版（GA）になり、File Uploads は近日提供とされました。MCP SDK の月間ダウンロードは7億を超え、Claude 向けコネクタは10,000を超えています。

        

      

      

        位置づけ： ツールを「配る」仕組みが MCP、使い方を「まとめる」形式が Agent Skills。Skills over MCP は、その2つを同じサーバーから一緒に届けるための拡張です。
      


      
      

        PROS / CONS
        
Skills over MCPの良い点と弱点

      

      

        
良い点：ツールと「使い方」が同じ出所から届く

        
開発者は、ツールの実装と、その正しい使い方・手順を1回のリリースでまとめて配れます。利用者はスキルを別途探してインストールする必要がなく、サーバーへ接続し直せば常に最新の説明書で作業できます。ツールの仕様と説明書がズレる問題が、構造として起きにくくなります。

        
良い点：段階的開示で、コンテキストを無駄遣いしない

        
接続時に届くのは名前と短い説明だけです。スキルの本文は、タスクに必要になったものだけが読み込まれます。サーバーが大量のスキルを持っていても、普段の会話に説明書の全文が載ることはありません。「たくさん配れる」と「軽く使える」を両立させる設計です。

        
弱点：スキルは「外部から来る指示」である

        
スキルは、サーバーが配る文章の形をした指示です。つまりモデルの振る舞いを左右する入力が、接続先のサーバーから届くということでもあります。悪意のあるスキルや改ざんされたスキルが紛れれば、モデルを望ましくない手順へ誘導するプロンプトインジェクションの入口になり得ます。スキルは「信頼できる説明書」ではなく「信頼できない入力」として扱うのが前提です。

        
そのための歯止めも仕様に含まれます。コードの実行やツール許可を含むスキルにはホスト側の承認が必要で、ファイルの内容が変わると承認は取り消されます（ダイジェストで変更を検知する仕組みです）。また Claude Code は、スキルが宣言する設定のうちツール許可やフックなどを無視します。管理者向けには、組織単位のスイッチや disableDirectMcpSkills のような無効化設定も用意されています。

        
弱点：仕様は固まったが、実装はまだ途上

        
拡張仕様 SEP-2640 は Final ですが、SDKとホスト側の実装は進行中です。使えるプランや有効化の条件も環境によって異なります。「規格がある」ことと「手元の環境でそのまま動く」ことの間には、まだ距離がある段階だと捉えておくのが安全です。

      


      

        NOTES
        
用語解説

      

      

        

          
スキルSkill

          
ツールの使い方の手順・ベストプラクティス・ワークフローをまとめた指示書。本文の SKILL.md と補助ファイルからなるディレクトリで、Agent Skills の形式に従います。

        

        

          
Agent Skillsオープン標準

          
スキルの形式そのものを定めた仕様。2025年12月にオープン標準化され、特定の製品に縛られない「説明書のファイル形式」として扱われます。

        

        

          
段階的開示progressive disclosure

          
最初は名前と短い説明だけを見せ、本文は必要になった時点で読み込む運び方。情報量の多いスキルを多数配っても、コンテキストを圧迫しないための工夫です。

        

        

          
skills 拡張io.modelcontextprotocol/skills

          
MCPサーバーがスキルを配布できることを示す拡張の識別子。サーバーは接続時の宣言で、この拡張に対応していることを伝えます。

        

        

          
server/discover発見

          
接続時にサーバーの能力を問い合わせるやり取り。ここで resources の能力と skills 拡張への対応が宣言され、ホストはスキルの発見に進めます。

        

        

          
skills/list・skills/getメタデータ取得

          
サーバーが配るスキルの名前や短い説明といったメタデータを返すリクエスト。本文は含まれず、モデルはこの情報だけを見てスキルを選びます。

        

        

          
resources/read実体の読み込み

          
選ばれたスキルのファイル実体（SKILL.md や補助ファイル）を読み込むための、通常のリソース読み取りリクエスト。必要なときだけ発行されます。

        

        

          
ダイジェスト変更検知

          
ファイル内容から計算される要約値。スキルの承認後に内容が変わるとダイジェストも変わり、ホストは「承認したものと違う」と検知して承認を取り消せます。

        

      


      
      

        CONCLUSION
        
まとめ

      

      

        
Skills over MCP は、MCPサーバーの配布物に「使い方の説明書」を加える拡張です。接続時に目次だけを発見し、タスクに合うスキルの本文だけを読み込み、その手順に沿ってツールを実行する。さらに更新はサーバー側で完結し、利用者は再インストールなしに新しい版へ追随できます。一方で、スキルは外部から届く指示でもあるため、承認やダイジェストによる変更検知といった歯止めとセットで捉える必要があります。「道具」と「説明書」を同じ出所から、必要な分だけ届ける――その配り方の規格化が、この拡張の持ち込んだ変化です。

      


      

        このページのサーバー名・スキル名・メッセージ内容は説明用の例です。提供条件やバージョンなどの数値は2026年11月24日の Anthropic の発表および MCP の拡張仕様（SEP-2640）に基づくもので、実際の挙動は利用するホスト／サーバーの実装によって異なります。
