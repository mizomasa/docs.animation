OPEN-SOURCE AGENT FRAMEWORK

Hermes Agentまとめ

Nous Research が公開する、自分のマシンやVPSに住む個人用AIエージェント。チャットアプリから話しかけると、道具を使って仕事をこなし、うまくいった手順を「スキル」として覚えて、使うほど賢くなっていく——その1日を、ロボットの作業場で追ってみます。

開発 Nous Research ライセンス MIT（オープンソース） 動く場所 自分のPC / VPS 売り 学習ループ
概要

Hermes Agentは、自分のPCやVPSにインストールして使う、オープンソースの個人用AIエージェントフレームワークです。

指示されたときだけ答えるチャット型の道具と違い、定期実行や外部からのメッセージをきっかけに自分で動き続ける、「常駐するエージェント」という形を実現するために生まれました。

成功した手順をスキルとして残し、会話をメモリに蓄積する学習ループによって、使うほど自分のやり方を覚えたエージェントに育っていきます。

背景

Hermes Agentが生まれた背景 — 「住むエージェント」という形態

チャットで完結しない仕事

LLMの使い方は、チャット画面で質問して答えを受け取る形から始まりました。しかし実際の頼みごとには、「毎朝決まった情報を調べて報告する」「メッセージが届いたら内容に応じて対応する」といった、時間や出来事に結びついたものが多くあります。こうした仕事は、人が画面を開いている間だけ動く道具では担いきれません。

さらに、頼みたい相手は1つのアプリの中だけにいるわけでもありません。普段使っているチャットアプリからそのまま話しかけられたほうが、日常の流れの中に組み込めます。

「自分の環境に住む」という発想

もう一つの要求は、置き場所です。クラウドのサービスに預けるのではなく、自分のPCやVPSの中で動き、自分のファイルや道具に直接触れられること。そうすれば、作業の文脈もデータも手元に置いたまま、エージェントに任せられます。Hermes Agentが「インストールして使う個人用エージェント」という形を取るのは、この要求への答えです。

性格や振る舞いをファイルで定義できる点も含め、「借り物ではない、自分のエージェント」という性格が、この設計の土台になっています。

経験を捨てないために

ただ常駐させるだけでは、セッションが替わるたびに同じ説明を繰り返すことになります。うまくいった手順と、会話で得た文脈を持ち越す仕組みがなければ、エージェントはいつまでも新人のままです。そこで、成功した手順をスキルとしてファイルに残し、会話をメモリに蓄積して次回に読み戻す、学習ループが中核に置かれました。

スキルは「やり方」、メモリは「出来事と文脈」と役割を分けたのも、持ち越すものを整理するためです。両方がそろって初めて、前回の経験が次回の動きに効いてきます。

ないとどうなるか

こうした常駐型の仕組みがなければ、定期作業はcronとスクリプトを自分で組み、メッセージへの対応はその都度人が行い、エージェントとのやり取りはセッションごとにゼロから始まります。手順の工夫も蓄積されません。「任せて、育てる」という使い方そのものが成立しない、というのが一番の違いです。言い換えれば、Hermesのような形態は、「AIに聞く」から「AIに任せる」への移行に必要な部品をそろえたものだと言えます。

アニメーションの「ロボットの1日」に沿って、動きを文章でもたどっておきます。

入口はたくさん、応対は1つ

Hermesの入口は、CLIやデスクトップアプリに加えて、TelegramやDiscord、Slackなど20以上のメッセージング連携（Gateway）があります。どの入口から話しかけても、応答するのは同じエージェントのコアです。入口ごとに別のエージェントが立つわけではないため、昨日の続きを別のアプリから話しかけても文脈はつながります。また、Cronに登録した定期タスクは、決まった時刻になると人の指示なしにエージェントを起こし、自然言語で書かれたタスクを実行させます。

道具を使って仕事をする

起きたエージェントは、ファイル操作、シェル、ブラウザといったツールを使って作業を進めます。ツールの実行結果はモデルに戻され、「考えて、道具を使い、結果を見て、また考える」というループが、タスクが完了するまで回り続けます。外部のツールはMCPで接続でき、実行環境はローカルだけでなくDockerなどのサンドボックスも選べます。大きな仕事はサブエージェントに分担させ、並行して処理させることもできます。モデルが「考える」だけでは仕事は終わらず、この「道具を使って手を動かす」部分がエージェントの実働を担います。

スキルとメモリに残す

タスクがうまくいくと、その手順は SKILL.md 形式のスキルとして自動でファイルに残ります。会話の内容はメモリとして蓄積され、全会話履歴が SQLite と全文検索（FTS5）の形で保存されるため、過去の文脈を検索して思い出すことができます。次に似たタスクが来たとき、エージェントはスキルを読み込み、メモリの文脈と合わせて、最初から効率よく動き始めます。

この記録と想起の往復が学習ループです。1回のセッションで得た経験がファイルとして残るため、エージェントの働きはモデルの性能だけでなく、蓄積されたスキルとメモリの質にも左右されるようになります。

頭脳を替えても同じエージェント

頭脳にあたるLLMは差し替え可能で、性格や振る舞いは SOUL.md というファイルで定義されます。モデルを替えても、スキル、メモリ、性格はそのまま引き継がれるため、「同じエージェントが、別の頭脳で働く」という状態になります。この分離があるからこそ、モデルの進化や価格の変化に合わせて、運用を止めずに頭脳だけを乗り換えることができます。道具と経験はエージェント側に残り、モデルは交換可能な部品として扱われる設計です。

まとめると、Hermesの動きは「入口で受け取り、道具で実行し、経験として残す」という循環です。アニメーションでロボットがステーションを巡るのは、この循環を1日の流れに置き換えたものにほかなりません。

Hermes Agentとは

Hermes Agent は、Nous Research が MIT ライセンスで公開しているオープンソースの自律エージェントフレームワークです。クラウドのチャットサービスとして使うのではなく、自分のPCやVPSにインストールして動かす「個人用エージェント」という位置づけで、入口はコマンドライン（CLI）、デスクトップアプリ、そして Telegram / Discord / Slack / WhatsApp / Signal など20以上のメッセージング連携（Gateway）があり、どれから話しかけても同じエージェントのコアが応答します。

最大の特徴は学習ループ（built-in learning loop）です。タスクがうまくいくと、その手順をスキルとして自動でファイルに残し、会話の内容はメモリに蓄積されるため、使えば使うほど「自分のやり方」を覚えたエージェントに育っていきます。性格や振る舞いは SOUL.md というファイルで定義でき、頭脳にあたるLLMも Nous Portal / OpenRouter / OpenAI / Anthropic / ローカルの llama.cpp などから自由に差し替えられます。

主な機能

アニメーションの各ステーションが、そのまま機能に対応しています。

↻学習ループ

成功した手順をスキル化し、メモリと組み合わせて次回に活かす、Hermes の売り。使うほど賢くなる設計です。

▦メモリ MEMORY

全会話履歴を SQLite ＋ FTS5（全文検索）に保存し、過去の会話を横断検索して文脈として思い出せます。

✎スキル SKILLS

手順書は SKILL.md 形式（agentskills.io 標準）。複雑なタスクの完了後に skill_manage で自動作成されます。

✉マルチプラットフォーム GATEWAY

CLI・デスクトップ・20以上のメッセージングアプリが入口。どの入口でも同じエージェントが応答します。

◉モデル自由 MODEL-AGNOSTIC

Nous Portal / OpenRouter / OpenAI / Anthropic / ローカル（llama.cpp）など、LLMを差し替えても本体はそのまま。

◷Cron SCHEDULED TASKS

定期実行も「自然言語で書いたエージェントタスク」として登録でき、決まった時刻に自律的に動き出します。

⧉サブエージェント SUB-AGENTS

大きな仕事は子エージェントに分担させ、並行して処理させることができます。

⚒MCP対応 TOOLS

ファイル操作・シェル・ブラウザなどのツールに加え、MCP（Model Context Protocol）で外部ツールを接続できます。

▣サンドボックス SANDBOX

ターミナルの実行環境はローカル / Docker / SSH / Modal などから選べ、隔離した環境で動かすことも可能です。

学習ループの仕組み

「スキル」と「メモリ」は役割が違います。スキルはやり方、メモリは出来事と文脈です。

STEP 1タスクを実行ツールを使って調べものや作業を行い、試行錯誤しながら完了を目指す
→
STEP 2うまくいったら記録複雑なタスクが成功すると、手順を SKILL.md として自動作成（skill_manage）
→
STEP 3メモリにも蓄積会話の内容は履歴として保存され、全文検索でいつでも引き出せる
→
STEP 4次回は賢く開始似たタスクではスキルを読み込み、メモリの文脈と合わせて最初から効率よく動く

つまり、スキル＝再利用できる「手順書」、メモリ＝検索できる「日記と文脈」。この2つが回ることで、エージェントはセッションをまたいで成長します。アニメーションのステップ5（ノートに書く）とステップ6（保管箱にしまう）がこの関係です。

危険性と対策

Hermes 自体がマルウェアというわけではありません。ただし「自分のマシンで自律的に動き、外部からも話しかけられる」設計そのものに、構造的なリスクがあります。

⚠ ローカル実行時の広い権限

シェルやファイル操作を自分のマシンで実行するため、誤動作や暴走の被害がそのまま自分の環境に及びます。

✓ 対策

Docker などのサンドボックス・バックエンドや専用のVMで動かし、本体環境と隔離する。

⚠ メッセージング入口の許可設定

Telegram や Discord が入口になるため、許可リストの設定ミスやアカウントの乗っ取りが、そのままエージェントの操作権につながります。

✓ 対策

入口は許可リストで利用者を絞り、アカウント側の認証も強固に保つ。

⚠ プロンプトインジェクション

メールやWebページなど外部の文章を読む機会が多いため、埋め込まれた指示に誘導されるリスクがあります。「機密へのアクセス × 信頼できない入力 × 外部送信」が揃うと危険です。

✓ 対策

重要な認証情報は渡さない。送信や削除など影響の大きい操作には承認を挟む。

⚠ スキル・メモリへの永続化

学習ループが悪意ある内容や間違った手順を取り込むと、消すまでセッションをまたいで効き続けます。

✓ 対策

保存されたスキルやメモリを定期的に見直し、出所の分からない内容は取り込まない。

サンドボックスで隔離 入口は許可リスト 重要操作は承認制 専用環境で運用 認証情報は最小限
強みと弱み

Hermes Agentの良い点と弱点

良い点：使うほど自分のやり方に合ってくる

学習ループにより、スキルとメモリが蓄積されるほど、エージェントは利用者の手順や文脈に沿って動けるようになります。自分の環境で動くため手元のファイルや道具と直結でき、頭脳のモデルも自由に選べます。入口が普段使いのチャットアプリであることも、日常に組み込みやすいという点で実用上の強みです。オープンソースで中身が見えることも、任せる範囲を自分で決めたい場合には安心材料になります。

弱点：自分のマシンで動くぶん、権限が広い

シェルやファイル操作を自分の環境で実行する設計上、誤動作や暴走の影響はそのまま自分のマシンに及びます。サンドボックスや専用環境で隔離する運用が前提になり、その手間も含めて「導入すれば終わり」ではない道具です。定期実行で人の見ていない時間帯にも動くため、異常に気づくのが遅れやすい点も挙げられます。

弱点：入口と学習ループが、そのまま弱点にもなる

メッセージングアプリが入口になる以上、許可設定のミスやアカウントの乗っ取りは、エージェントの操作権に直結します。また、外部の文章に埋め込まれた指示に誘導されるプロンプトインジェクションのリスクは、メールやWebを読む機会が多いほど高まります。さらに、間違った手順や悪意のある内容がスキルやメモリに取り込まれると、消すまでセッションをまたいで効き続けます。保存された内容を定期的に見直す運用が欠かせません。

弱点：育てる手間と、かかり続けるコスト

スキルやメモリは自動でたまりますが、質を保つには棚卸しが必要です。また、常駐して定期実行するぶん、モデルの利用料金やマシンの稼働コストは継続的にかかります。自律的に動く範囲を広げるほど、任せる仕事の選別とコストの見通しが重要になります。

似たOSSとの違い

vs OpenClaw

よく比較される類似OSSの OpenClaw との大きな違いは、「学習ループ」を中核に据えている点です。成功した手順をスキルとして自動で残し、メモリと組み合わせて育てていく設計が Hermes Agent の個性です。

どちらも「自分の環境に住む個人用エージェント」という方向性は共通しているため、乗り換えや併用を検討する文脈で並べて語られることが多い組み合わせです。

まとめ

Hermes Agentは、自分の環境に常駐し、道具を使って働き、経験をスキルとメモリに残して育っていく個人用エージェントです。入口の多さ、モデルの自由さ、学習ループがその個性であり、同時に、広い権限と外部への入口を持つことのリスクと表裏一体でもあります。便利さを引き出す鍵は、隔離と許可と承認という歯止めを、運用の中でどう設計するかにあります。「聞くためのAI」から「任せるためのAI」へ。その移行に必要な部品と、その代償の両方を見せてくれる存在だと言えます。

本ページは Hermes Agent（Nous Research）の公開情報に基づく一般的な技術解説です。アニメーションは仕組みを分かりやすく表した概念図であり、実際のUIや動作そのものではありません。
